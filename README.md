# 高峰用电风险协调平台

能源运行部门的负荷风险协调平台：持续接收地区与行业计量、气象观测、设备检修和
充换电需求，按版本保存预测，安排日内预警与需求响应，并在事后对照实际削峰、
未履约容量与异常数据误报进行复盘。

## 值班场景覆盖

- **最大负荷刷新纪录的值班日**：在月报形成前判断数据中心、充换电、高端制造的
  增长是否挤压局部备用容量（红/橙/蓝三级备用率预警）。
- **台风降雨的短期扰动**：居民用电下降被显式标记为瞬时项（`transient_flags`），
  与长周期行业增长分列，不会被当成趋势写进月报，也不外推到跨日峰谷。
- **迟到读数与计量更正**：原始观测只追加、永不改写；更正以 `supersedes` 追加
  新读数，异常以只追加的标记记录。重算只发生在受影响时窗，其余时窗从上一版本
  原样沿用（`carried_from`）。
- **企业退出 / 调度撤回**：指令状态事件化，已分配容量即时恢复并可改派；
  新版本预警不再覆盖某时窗时自动对账撤回。
- **企业隔离视图**：参与企业只能收到本企业的行动要求。
- **逐项可解释**：每条预警列出贡献分解、所用观测 `obs_id` 与生效假设。
- **事后复盘**：对照预测/实际备用、企业关口计量算出的实际削峰与未履约，
  并识别“异常数据引发的误报”。

## 模块

| 文件 | 职责 |
| --- | --- |
| `src/timewin.py` | 统一 15 分钟时窗 |
| `src/ledger.py` | 不可篡改观测台账（追加、更正链、异常标记、`as_of` 时点视图、跨日峰谷派生） |
| `src/forecast.py` | 透明预测模型、预测版本、受影响时窗增量重算 |
| `src/alerts.py` | 局部备用容量预警、缺口计算、逐项解释 |
| `src/response.py` | 资源注册、比例分配、退出/撤回容量恢复、企业隔离视图、结算 |
| `src/review.py` | 预测偏差、履约结算、异常数据误报复盘 |
| `src/platform.py` | 日内值班编排：接入 → 增量重算 → 预警 → 对账分配 → 复盘 |
| `examples/typhoon_day.py` | 台风降雨日全流程演示（合成数据） |

预测模型保持透明可核对：

```
预测负荷 = 规划基准曲线
         + 最新实测相对基准的偏移（惯性持续项，迟到读数借此影响相邻时窗）
         + 数据中心增长 + 充换电增长 + 高端制造增长
         + 充换电预约增量
         + 高温制冷调整
         - 台风降雨导致的居民短期下降（瞬时项，单独标记）
```

每个版本冻结自己的假设（增长率、制冷系数、台风阈值等）和每个时窗所用观测的
`obs_id`；`as_of` 时点视图保证早时窗生成的版本看不到之后才到的读数，
月报形成前的任意时点都能严格复现当时依据。

## 运行

```bash
python -m unittest discover -s tests   # 19 项测试
python -m examples.typhoon_day         # 台风日全流程演示
```

仓库不保存账号、密钥、连接串或真实身份信息；示例数据全部为合成数据。
领域资料结构见 `contracts/domain.schema.json`，`src/domain.py` 负责其基础校验。
