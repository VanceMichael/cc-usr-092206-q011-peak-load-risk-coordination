# 高峰用电风险协调

结合计量、气象和行业需求形成可解释的高峰用电响应。

## 平台能力

`src/` 实现能源运行部门的负荷风险协调平台，覆盖值班日全流程：

- **数据接入**（`observations.py`）：持续接收地区与行业计量、气象观测、设备检修、
  充换电需求。观测只追加不改写；计量更正以新观测链接原观测，原始读数始终可取回；
  跨日峰谷等统计在读时派生，从不会回写原始观测。
- **版本化预测**（`forecasts.py`）：预测结果按版本保存、可回溯。迟到读数、计量更正
  或新预测请求只重算受影响时窗（按取数依赖定位），未受影响窗口自上一版本原样结转。
  台风/强降雨造成的居民用电下降按短时扰动处理，只修正受影响时窗，不计入长期趋势；
  数据中心、高端制造按日增速外推，充换电需求按申报叠加，全部假设随窗口结果保存。
- **日内预警**（`risks.py`）：按当前预测版本逐窗口计算备用裕度（可用容量 = 装机 −
  检修停运），低于阈值分级（提示/预警/严重）。每条预警附逐项解释——数据项、来源
  观测 id 与假设，分析人员可逐项核对。
- **需求响应**（`response.py`）：按预警缺口向企业分配削峰指令，容量台账按
  (地区, 时窗) 记账。企业退出响应或调度撤回指令时，已分配容量立即恢复并写入审计
  日志；企业视图仅返回本企业的行动要求。
- **事后复盘**（`review.py`）：对照预测与实际有效计量，统计实际削峰、未履约容量
  （企业退出、部分履约均计入；调度撤回不计为企业承诺），并识别异常数据引发的误报
  （质量标记异常或事后被更正的观测）。
- **平台门面**（`platform.py`）：串联接入 → 预测 → 预警 → 响应 → 复盘；
  `tests/test_platform_e2e.py` 给出最大负荷刷新纪录值班日的完整示例。

## 领域资料

`contracts/domain.schema.json` 规定共享资料结构，`fixtures/domain.json` 保存不含真实个人信息的示例。当前参与方包括能源运行部门、电网调度人员、用电企业、需求响应服务方。

资料所依据的领域事实如下：

- 月度全社会用电量再次超过万亿千瓦时
- 最大负荷创历史新高且多日超过上年峰值
- 充换电和互联网数据服务用电增长明显

## 本地校验

仓库内的读取模块负责校验示例资料的领域标识、版本、参与方、事实和约束。运行项目自带测试即可检查这些基础资料能够稳定读取。仓库不保存账号、密钥、连接串或真实身份信息。

python3 -m unittest discover -s tests
